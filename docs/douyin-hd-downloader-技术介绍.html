它做什么、不做什么

解析一条用户有权保存的公开抖音作品，枚举真实视频源，默认优先上传原片。下载只保存字节流，禁止用 ffmpeg 转码。

四端（Claude / Cursor / Codex / Grok）都软链到同一份 git 仓库：~/Work/claude-skills/skills/douyin-hd-downloader。改仓库，四端读到的是同一份。

做

完整 URL、短链、整段分享文案。inspect → download / compare。原片与转码对比。ffprobe 验证。Cookie 只从环境变量读。

不做

私密、付费、登录墙、地区绕过。主页批量、收藏、评论、直播。任意 URL 代理。自己实现 a_bogus 一类易失签名。

为什么必须走 run.sh

PATH 上的 python3 不一定能跑这个工具。2026-08-23 在这台 Mac 上测过：/usr/bin/python3 是 3.9.6 且没有 httpx；同机 /opt/anaconda3/bin/python3 是 3.12.4，可用。

最低版本是 3.10（dataclass(slots=True)）。文档曾经误写成 3.11+，已改。

run.sh 按顺序探测候选，挑第一个同时满足「≥ 3.10 且能 import httpx」的解释器。可以用 DOUYIN_PYTHON 钉死。挑不到会说明该装什么，不静默失败。不把某一台机器的路径写进文档——这个 skill 是四端共用的。

输入怎么变成作品 ID

接受三种输入：完整作品页、短链 v.douyin.com/…、整段「复制打开抖音…」文案。

  1. 正则抽出 URL，剥掉中英文后置标点。
  2. 域名必须在精确白名单里：douyin.com / www.douyin.com / v.douyin.com / iesdouyin.com 及其 www / v。douyin.com.evil.com 会被拒。不允许 URL 里带用户名密码。
  3. 从 path 或 query 抽数字 ID：/video|note|slides/、/share/video/、aweme_id / item_ids / modal_id。
  4. 短链没有 ID 时，手动跟随最多 8 次 30x；每一跳都重新验域名，不交给 httpx 自动跟随。

已经带 ID 的完整链接不发网络请求。

两条 metadata 路径

快路径：iesdouyin SSR

请求 https://www.iesdouyin.com/share/{video|note}/{id}/，用 iPhone UA。桌面 UA 更容易只拿到页面壳。

页面里找两处嵌入数据：

  • window._ROUTER_DATA = {…}：用感知字符串的大括号深度抠 JSON。惰性正则会被字符串里的 } 截断。
  • id="RENDER_DATA"：HTML unescape，必要时再 percent-decode，然后 json.loads。

在整棵 JSON 上 DFS，找带 video 字典的作品，优先 aweme_id 完全匹配。只有 itemId、没有 video 的壳不算成功。

必须重试。 2026-08-22 实测：单次大约 4/6 成功，不超过 3 次独立请求则 6/6。间隔 0.8s × 次数。页面壳是常态抖动，不是风控。

风控只认真挑战标记：waf_js、wafchallengeid、/waf-jschallenge/、/captcha/、slardar_captcha。不要用 verifyCenter——正常页 6/6 都带这个 SDK 名，用了会把普通抖动误报成 WAF，把人赶到 Cookie 和代理上。

慢路径：真实 Chrome（默认关）

只在显式 --browser-fallback，并且 SSR 失败、或有播放地址但缺少 video.bit_rate[] 时启动。Playwright 先开本机 Chrome，失败再试自带 Chromium。打开 www.douyin.com/video/{id}，等页面自己发出的 /aweme/v1/web/aweme/detail/，读 JSON。签名由页面生成，本项目不维护 a_bogus。

Cookie 只从环境变量读（默认 DOUYIN_COOKIE），不落盘。浏览器侧种在 .douyin.com。

候选从哪来

build_variants() 从 item.video 抽出逻辑档，不是抓到第一条 CDN 就下。

source_type来源干什么
original 用 uri 拼 /aweme/v1/play/?ratio=default&watermark=0&source=PackSourceEnum_PUBLISH 上传原片探测。不是 bit_rate[] 最高档。
bitrate video.bit_rate[] 每档一条，可带多个 CDN mirror highest / 1080p / compatible 的主集合
play_addr play_addr / _h264 / _265 URL 集合与转码档不重复才加入
download_addr download_addr 同样去重；不参与 highest 排序

编码从 is_h265 / is_bytevc1 / codec 或 key 名推断。http:// 和 // 会升成 https。original 这条 URL 是 best-effort，不是永久 CDN 规则；它挂了只影响 original，不能拖死 highest。

怎样确认「这是视频」

每个候选的 mirror 顺序发 GET，带 Range: bytes=0-65535。不并行——这是单条检查，不是爬虫。

通过条件：HTTP 200 或 206；body 真像视频（video/*，或前 64 字节有 ftyp / WebM EBML）。HTML / JSON 风控页即使 200 也失败。

体积优先读 Content-Range 的 total；200 才信 Content-Length。probe 成功后用这个长度覆盖 metadata 里的 file_size_hint。

每次跳转都要求 HTTPS，并且 DNS 解析结果必须是公网地址。拒私网、回环、链路本地、组播、保留、未指定、localhost。媒体 URL 只能来自 Douyin metadata 或由其 uri 拼出，调用方不能塞任意下载地址。

瞬时失败不是结论

ConnectTimeout / ReadTimeout / 5xx / 429 最多再试 6 次。403 / 404 不重试。connect timeout 压到 3.5 秒：健康边缘大约 0.3 秒，坏边缘会吃满上限；以前 10 秒的 connect 预算，一个坏边缘就烧光重试窗口。

实测：一次 10.4 秒的 ConnectTimeout 曾把 original 判死，静默掉到 2.8 MiB 水印档。马上重探同一 URL，两次都是 206 / 约 45 MB。一次超时 ≠ 原片不存在。

怎么选档

highest 的排序键是 (宽×高, 码率, 探测体积)。只在 probe 成功的 bitrate 里比；没有才退到 play_addr。

--quality行为
original（默认）原片 probe 成功且体积大于最高转码档才用。否则 fallback。若 fallback 目标是水印源 → 报错中止。
highest按上面排序。不管水印，但会打印 warning。
compatible有效 H.264 里再排序。不转码，也不谎称验过 AAC。
1080p / 720p / 540p短边或 gear_name 匹配该数字。
play_addr仅 compare 的 --include-play-addr。

水印不能信 has_watermark 字段（实测水印候选上是 None）。认 URL 路径里的 /playwm/。

当 bit_rate[] 为空，highest 会退化成 playwm。如果 --quality original 此时静默 fallback，会把 2.8 MiB 带 logo 的文件当原片交出去。现在必须报错，让人重试，或显式接受 --quality highest。

original 不等于「最高转码档」。固定样例里原片更大、更高帧率；也存在超分转码比原片更大的反例，所以要比探测体积，不能只看标签。

下载与验证

  1. URL 顺序：probe 后的 resolved_url，再各 mirror。
  2. 写到 <name>.part，1 MiB 一块流式写，同时算 sha256。
  3. 第一块再验一次是不是视频。
  4. 实际字节数必须等于 Content-Length / Content-Range total。
  5. os.replace 原子改成最终文件名。
  6. 失败或异常删除 .part。
  7. ffprobe 只要确认有 video stream。不做 ffmpeg 重编码。

传输错误按 0 / 1 / 2 / 5 秒重试。403 / 404 换下一条 mirror。

Ctrl-C 只打印「已取消。」不承诺 .part 已经清掉：inspect 阶段根本没有 part 文件；中断若落在 asyncio.run 之外，清理也不一定跑到。真正负责清理的是 download_variant 自己的 finally。

控制台和 JSON 用 safe_url_parts()：只留 host 和截断 path，丢掉 query（签名、token）。Cookie 不进候选 JSON。

compare 会下载 original 和 highest（可选 play_addr）。同一 URL 不重下，写 comparison.json 和各自的 ffprobe。

安全与隐私

  • 输入域名精确白名单，短链每跳重验。
  • 媒体只能来自 Douyin metadata 或其中的 uri。
  • 媒体每跳要求 HTTPS + 公网 DNS。
  • 输出脱敏，不打印 CDN query、签名、Cookie。
  • Cookie 只从指定环境变量读，不落盘。
入口不是开放代理。仍在的缺口：httpx 全局 cookie jar 会把会话带到 CDN；DNS 校验和真实连接不是同一次解析，存在 rebinding 窗口。

解析：resolver.py

ALLOWED_HOSTS 是 frozenset 精确匹配，不是后缀匹配。extract_url() 用 URL_RE 扫文案，rstrip(TRAILING_PUNCTUATION) 后再 validate_input_url()；第一个合法抖音链接胜出。

extract_aweme_id() 两套正则：path 上的 /(share/)?(video|note|slides)/(\d+)，以及 query 的 aweme_id|item_ids|modal_id。

resolve_input() 已有 ID 就立刻返回 ResolvedInput。否则对短链 GET，带 Range: bytes=0-0，follow_redirects=False。301–308 用 urljoin 拼 Location，再验白名单；超过 8 跳报错。

SSR JSON：_balanced_json_object

不能用 \{.*?\}。从第一个 { 起扫，维护 depth / in_string / escaped。字符串里的 } 不加深度。回到 depth 0 时切出子串再 json.loads。测试里专门放了 "brace } inside a JSON string"。

def _balanced_json_object(text, start):
    depth = 0
    in_string = False
    escaped = False
    for index in range(start, len(text)):
        char = text[index]
        if in_string:
            # 处理 \\ 与 \"
            ...
            continue
        if char == '"':
            in_string = True
        elif char == '{':
            depth += 1
        elif char == '}':
            depth -= 1
            if depth == 0:
                return text[start:index + 1]

extract_embedded_data() 先找 window._ROUTER_DATA / _ROUTER_DATA，再退到 id="RENDER_DATA"：html.unescape 后先原样、再 unquote 各试一次。

find_aweme() DFS 整棵树。_looks_like_aweme 要求有 video 字典；id 匹配进 preferred，没有 id 的进 fallback。返回 (preferred or fallback or [None])[0]。只有 itemId 的壳进不了，因为没有 video。

SSR 重试与 Chrome：providers.py

_fetch_ssr_once() 依次试 /share/video/ 和 /share/note/，iPhone UA。非 200、WAF、没有嵌入数据、壳页，都记进 reasons 并继续。WAF 标记是元组 WAF_MARKERS，不含 verifyCenter。

fetch_from_ssr(attempts=3, retry_delay=0.8)：每次独立请求；失败则 sleep(0.8 * (attempt+1))。三次都失败才 ProviderError。

fetch_metadata()：SSR 成功且（有 bit_rate 或没开 browser-fallback）就返回 iesdouyin_ssr。SSR 有播放地址但缺阶梯、且开了 fallback，再走 Chrome。

fetch_from_browser() 用 Playwright：先 channel=chrome（可用 DOUYIN_BROWSER_CHANNEL 改），失败再无 channel 的 Chromium。在 page.goto 外包 expect_response，URL 含 /aweme/v1/web/aweme/detail/。读 aweme_detail，再用 _looks_like_aweme 校验。Cookie 解析成 name=value，种在 .douyin.com / path=/ / secure。

编排与超时：pipeline.py

CONNECT_TIMEOUT_SECONDS = 3.5。make_client()：

timeout = httpx.Timeout(timeout_seconds,
                        connect=min(timeout_seconds, 3.5))
httpx.AsyncClient(
    headers={Desktop UA, Referer: https://www.douyin.com/},
    cookies=parse_cookie_header(cookie_header),  # 全局 jar，也会带到 CDN
    timeout=timeout,

默认读超时 35s，下载客户端会抬到至少 120s。inspect_public_aweme() 在 probe 前强制：metadata 的 aweme_id 必须等于解析出的 ID；一个 candidate 都没有则 RuntimeError。

normalize_aweme() 抽 author.nickname、desc、duration（作品级或 video 级），然后 build_variants(item)。

造候选：build_variants()

先扫 video.bit_rate[]，每档取 play_addr / playAddr，extract_urls() 读 url_list / urlList / 嵌套 url。// 和 http:// 升成 https。去重键是 (gear_name, width, height, bitrate, codec)。

再补 play_addr_h264 / play_addr_265 / play_addr / download_addr，整组 URL 已出现过就跳过。

第一个带 uri 的档用来拼 original，插到列表最前：

params = {

    "ratio": "default",

infer_codec()：is_h265 / is_bytevc1 为真 → h265；字段名在但值为 0 → 当成 h264；key 名带 265 / h264 也可。

Probe：_probe_url / probe_variant

最多 8 跳。每跳先 validate_public_media_url()：必须 https、有 hostname、无 userinfo；字面量 IP 和 getaddrinfo 结果都要过 _is_public_ip（排除 private / loopback / link-local / multicast / reserved / unspecified）。

然后 client.stream("GET", headers={"Range": "bytes=0-65535"})。30x 继续；否则读最多 64 KiB。_looks_like_media：video/* 直接过；否则看前 64 字节有没有 ftyp 或 WebM 头 \\x1aE\\xdf\\xa3。体积：Content-Range 的 /total 优先，200 才用 Content-Length。

probe_variant(attempts=6, retry_delay=0.3)：对外层每个 URL，内层最多 6 次。成功则写回 variant.probe，并用 content_length 覆盖 file_size_hint。瞬时错误（超时类异常名，或 408/425/429/5xx）才 sleep 再试；403/404 换下一条 URL。probe_all() 顺序扫全部 candidate。

选档：select_variant

_score(v) = (width*height, bitrate, file_size_hint)   # 缺省当 0
_valid_transcodes = probe 成功的 bitrate，否则 probe 成功的 play_addr
highest = max(transcodes, key=_score)

original:
  有 probe.ok 的 original，且 (not highest_size or original_size > highest_size)
    → 选 original
  否则若 is_watermarked(highest)   # has_watermark 或 URL 含 /playwm/
    → MediaError（区分「没有原片候选」和「有但 probe 失败」）
  否则 → fallback 到 highest

1080p/720p/540p:
  short_edge == N  或  gear_name 匹配 (^|_)N(_|$)

is_watermarked() 先看字段，再扫 variant.urls 是否含 /playwm/。字段为 None 时只靠路径。

下载：download_variant

URL 列表：[best_download_url, *variant.urls] 去重保序。对每条 URL 按 delay 0, 1, 2, 5 秒重试。_stream_download_once 同样手跟最多 8 跳，每跳验公网 HTTPS，流式写 .part（1 MiB 一块），边写边 hashlib.sha256。第一块再验视频。空文件或长度对不上就 MediaError。成功则 os.replace(part, dest)。

TransportError / TimeoutException 删 part 再试同一 URL。MediaError 含 HTTP 403 / 404 则换 mirror；其它 MediaError 仍按 delay 重试。外层 except BaseException 保证中断时也删 part。

run_ffprobe() 调系统 ffprobe -show_entries format=…:stream=… -of json，没有 video stream 当失败。ffprobe_summary() 抽出分辨率、视频/音频 codec、fps、码率、时长、体积。

CLI：douyin_hd.py

三个 subparser 共用 --browser-fallback、--cookie-env（默认 DOUYIN_COOKIE）、--timeout 35、--debug。download / compare 的 --output 默认 ~/Downloads/douyin，实际文件在 <output>/<aweme_id>/。

JSON 用 _atomic_json：写 .tmp 再 os.replace。debug 打印 host/path/content-type/length，不打印完整 URL。

compare 用 best_download_url 当 identity，同一 URL 的 mode 记 same_as，不重下。

实测钉死的不变量

这些不是设计幻想，是 2026-08-22 连续跑出来的。改代码时不要为了「看起来更干净」拿掉。

  1. 瞬时失败必须重试，不能当结论。SSR 空壳、original ConnectTimeout 都是抖动。联网验收建议连续至少 5 次。
  2. original 绝不能静默交出 /playwm/。
  3. WAF 判据不能用厂商 SDK 名。
  4. connect timeout 要短（3.5s），否则坏边缘吃掉整个重试窗口。
  5. 一次成功证明不了可用性。 首版就是这样把大约 30% 的失败率漏过去的。

单测 17 个、不联网：解析、括号 JSON、verifyCenter 不是 WAF、体积比较、水印拒绝、瞬时错误分类。集成测试只锁 aweme_id、至少一个有效候选、存在 original 路径；不锁 CDN、分辨率、码率。

已知缺口

评审里提过、还没改或只改了一部分的：

  • original 在「两边体积都未知」时仍可能胜出，和文档「体积未知应回退」不完全一致。
  • original 只拼了 line=0，没有把 line=1 做成同一候选的 mirror。
  • 输入白名单没有 m.douyin.com；/slides/ 能抽出 ID，但 SSR 只试 video / note。
  • Cookie 会跟到媒体 CDN；DNS 校验未钉到实际连接的 IP。
  • 媒体安全路径、下载 .part 清理的单测仍然偏少。
