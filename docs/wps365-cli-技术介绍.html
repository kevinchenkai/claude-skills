它做什么、不做什么

用本机官方 wps365-cli 操作金山协作和智能文档。不改走浏览器 Cookie CLI，不手写未验证的 OpenAPI。

查端点优先本机 spec：~/Library/Application Support/wps365-cli/spec/api.yaml，和二进制版本绑定。官方 wiki 讲流程，不保证字段一致。

做

搜索、读正文、导出 md/docx、建 otl 灌 Markdown、二进制上传、整理目录。案例见 references/demos.md。

不做

不重跑已完成环境的 config init（会换应用绑乱授权）。不改别人共享盘里的原件。不提交 token。

鉴权

用 user me -o json 判活。 access token 两小时，auth status 天天 expired，但 refresh 一年、下次真调用会续。照 status 会天天误报要重新登录。

只有 user me 真失败才看 auth status --jq '.delegated | {status, granted_scopes, has_refresh}'。缺哪条 scope 补哪条；没有 refresh 才 device login。

资源名一律单数：drive file。v0.2.0 起 drive files ... 不报错，退回打印帮助、exit 0，stderr 一句 unknown flag。脚本看 $? 会当成功。要看有没有 code:0 的 JSON。错命令的 --help 也是 0。

drive_id 跟着文件走

这是最容易犯的错。search 是全公司跨盘。实测 20 条命中能横跨 8 个盘。搜到 file_id 后套默认 6lABZaR 会打到错误的盘。

盘错时报 400008009 文件不存在，看起来像删了。先 file-path get <drive> <file>：换对盘能出祖先链，就说明文件还在。

drive list 只列你名下的盘（企业文档、自动备份），看不到共享盘。共享盘可读也可写，id 只能从 search 拿。往共享盘新建自己的产物可以；别人的原件不改不删。

命中多条且用户没指定时，列出 name + path + drive_id + 修改时间让人挑，不要自己选「看起来最像」的——跨盘同名会读错人的文件。

定位与读写

wps365-cli drive file search --type all --keyword "文档名" --page-size 20 -o json
wps365-cli drive file list 6lABZaR <parent-id> --page-size 100 -o json
wps365-cli drive file-content get <drive> <file> --format markdown -o json --jq '.data.markdown'

--type all 必填。列表在 data.items（不是 data.files），分页 next_page_token。搜索每条是 {file, file_src, highlights}。

根下有几乎同名的「01.技术交流文档」和「03.技术交流文档」，内容零重叠。用户说「技术文档」必须先确认是哪一个。表里的 folder_id 换环境要整表替换。

别拿文件体积估超时。176MB 的 otl，file-content get 约 0.5s（体积几乎是内嵌图）。默认 30s 目前没撞过，不要一见大文件就加 --timeout。

二进制上传

CLI 到 v0.3.2 仍无 upload 精装命令。三步：request_upload → PUT 实体 → commit_upload。两个 api post 都要 --token-type delegated。

公网第 1 步必须同时给：hashes 里 md5 + sha256 两种，以及 upload_scene: "normal_upload"。少一个报 400000004 请求参数不支持——看起来像接口没开，其实是参数不全。官方 spec 的 required 只写了 size，公网更严。

on_name_conflict 在上传端点只认 rename / overwrite。spec 里的 fail / replace 会被拒。建文件夹时 fail 却是好用的：同一枚举，不同端点。

完整性对 commit_upload 返回的 sha1。不要下回来比对：download url 另要鉴权，裸 curl 会拿到 46 字节 userNotLogin，算 md5 会得出「文件坏了」。

智能文档与跨盘复制

建档：POST /v7/airpage/files，name 必须自带 .otl（按最后一个点切扩展名，00.月报 会 400）。template_id 空串。rename 重名静默变 (1).otl 且仍 code:0，失败重试前先确认上次是不是其实成功了。

灌 Markdown：convert（arg 为 base64 的 json）→ 取出 blocks → create 插到 blockId=doc、index=1000000000。长文按 ## 切，每块 <18KB。

API 建的文档标题栏一定空。convert 不产出 title block，# H1 变成 heading。网页打开会用 H1 补 title，并可能改文件名。不要因为看到 Enter title 就重插。

drive file create --file-type otl 会 400，otl 只能走 airpage。

跨盘复制

不要 markdown 中转（丢表丢图）。读源 blocks，去掉 title、所有 id、所有 rangeMarkBegin/End（评论锚点，接口拒绝，正文不在里面），按 ≤9KB 切块插入。

batch-copy 从别人的共享盘往外拷静默失败：code:0 + task_id，目录里什么都没有。自己盘内复制立刻成功。判成功必须回查目标。

导出 docx

官方 export_to_docx 可用。attrs / version / ai_check 全必填。第一次几乎必然 Building + 空 url，要轮询，不能只打一次。

version 从 GET /v7/airpage/{id} 取；实测不做校验，随便一个数也能导出，不要因为 version「可能不对」怀疑结果。

取 url 用 Python json.load，不要 --jq：jq 会把 & 打成字面量，签名 URL 直接 AccessDenied，得到约 600 字节 XML。

验收三连：Completed → url 非空 → file 报 Microsoft OOXML。

目录治理

递归清单 → 归位表 → 等确认 → create + batch-move → 删空旧夹 → 回传树。批量搬/删前 --dry-run。一次大约 20 个 id。异步，轮询到源目录变空。

batch-move 重写 mtime，不可恢复。治理前先把名字/日期/体积存下来。folder 的单文件 delete 会 403，空夹用 batch_delete API。删正文先问用户。

红线

  • file_id 必须带它自己的 drive_id。400008009 先怀疑盘。
  • 单数资源名。判成功看 JSON，不看 exit code。
  • markdown 抽取不能验收含表文档，也不能当跨盘中转。
  • code:0 不等于内容到位。batch-copy / rename / 错命令都是例子。
  • 只动指定目录；共享盘原件只读。不提交 secret。
  • 交付给用户：文档名、建档返回的 link_url、本地路径、做了什么。
