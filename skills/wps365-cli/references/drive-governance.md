# Drive 目录治理与去重

用于“梳理目录、归档、去重、批量移动、删除空目录”等任务。用户只要求“梳理”时默认只读盘点；只有明确确认执行后才修改。

## 1. 默认目录原则

- 根目录不放正文；既有体系使用两位编号时延续 `01.`…`07.`，临时目录使用 `99.`，不擅自重排含义。
- 大于约 20 MB 的 pptx/pdf/mp3 等二进制资料进入 `附件/`；同文双格式优先保留 `.otl` 主文档，
  `.docx` 作为附件。
- `.otl` 是智能文档，不把普通 PDF/DOCX 改后缀伪装成 `.otl`。
- 20 MB 规则不适用于 `.otl`：内嵌图片会让智能文档很大，不能把正文主文档误归为附件。
- 已经治理过的目录只补缺口，不反复搬动。

## 2. 只读盘点

盘点至少记录：

| 字段 | 用途 |
|---|---|
| `drive_id + file_id` | 唯一操作身份 |
| 名称、类型 | 分类与冲突判断 |
| 父目录与完整路径 | 确定实际范围 |
| 大小 | 二进制重复判断 |
| 创建/修改时间 | 辅助证据，不能单独判重 |
| 正文摘要或块统计 | 智能文档内容判断 |

先列目标目录和相关子目录；检查分页。输出“当前结构、问题、建议目标结构、拟移动项、疑似重复项、风险项”，等待用户确认。

## 3. 重复判断

同名、`(1)`、`-copy`、`副本` 后缀、旧日期或相同大小都只能作为线索，不能单独作为删除依据。
副本可能比原件多出后续编辑，也可能根本没有对应“正本”。

### 普通二进制文件

优先比较：文件大小 → SHA-256 → 可打开性/文件类型。哈希一致才可高置信判为字节级重复。

### 智能文档

比较：

- 标准化标题和正文文本。
- 块类型、块顺序和关键结构。
- 表格、图片、附件数量与内容。
- 来源链接、创建者和路径。

Markdown 相同不保证复杂块完全相同；必要时导出 JSON/DOCX。无法高置信确认时保留两份并报告差异。

## 4. 执行计划

执行前把每个动作固定为显式映射：

```text
<source drive_id>/<file_id> -> <target drive_id>/<folder_id>
```

不要用未解析的环境变量、模糊名称或宽泛 glob 作为移动/删除目标。若涉及目录改名、跨盘移动、覆盖或删除，计划中要单独标记并获得确认。

推荐顺序：

1. 创建缺失的目标目录。
2. 移动低风险、唯一匹配的文件。
3. 回读目标路径和内容。
4. 处理经确认的重复项。
5. 最后删除已确认为空且无保留价值的目录。

批量操作优先使用官方 CLI 的 batch 能力，先 `--dry-run`，再保留 task id 并轮询。不要临时手写未经验证的批量 API。

## 5. 时间与版本陷阱

移动文件可能刷新 mtime，因此移动后的修改时间不能证明内容最近更新。判断版本优先使用正文差异、来源、版本信息和创建时间；若要保留时间证据，在移动前记录快照。

“最新”也不总等于“应保留”：实验记录、评测结论、任务说明书等历史版本可能具有长期价值，应按用户业务语义保留。

## 7. 删除边界

- 删除前再次列出精确文件 ID、路径和删除理由。
- 只删除用户确认范围内、高置信重复或明确废弃的对象。
- 不因为文件名不规范、位置不理想或目录暂时为空就自动删除。
- 删除后复查源目录、目标目录和幸存集合。
- 不能确认可恢复性时，优先移动到归档/待确认目录，而不是删除。

## 8. 最终验收

完成后至少报告：

- 移动、创建、跳过、删除、失败的数量。
- 每个关键对象的最终 `drive_id + file_id + path`。
- 目标目录树或清单。
- 操作前后完整文件 ID 集合与总字节数；不能只比条数。
- 智能文档的正文/块结构抽查结果。
- 因权限、歧义或低置信度而保留的项目。

若只完成部分动作，不要用“已完成整理”概括；明确列出剩余项和原因。
